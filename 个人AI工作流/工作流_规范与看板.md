# 第一部分：执行规范

## 0、通则

1. **唯一决策锚**：每个项目/集从《创作共识》(S0) 起步，后续一切以锚与依据链为准；
2. **题材包前置**：无题材包 → 该处引用停（缺负面词/红线/考据源/结构档/声学档则对应阶段停机提示），不替用户编造默认标准；
3. **版本追溯**：产物头固定 `状态(草稿/待确认/定稿)｜版本｜依据产物版本｜变更原因｜检点记录｜@下游`；
4. **制片人代用户把关**，不代创意；用户只在 终裁 / 细化 / 创意裁决 入场；
5. 工具无关、纯文件驱动；团队成员化开关见第九节。

## 3、执行规则 #1 · 用户修改执行规范

> 适用于任何 Agent 收到"用户提出与现行原文不一致的想法"时。

1. **触发**：用户口头/文字给一个与文件现有内容不同的改法。
2. **禁止**：直接改动上文/上下文；自行推定改动范围；用记忆里的旧文判断"哪句是原文"。
3. **必做 · 先问改动范围**：落点（哪一处）｜基准（当前以哪一版/哪份为现行稿）｜边界（只动所指，还是连带上游/下游）。
4. 得到答复才动手；动手前**重读磁盘现行文件核对**，不凭记忆。
5. 用户选"仅改所指处"但确有上下文矛盾 → 产物头记 `【遗留矛盾】…`，不静默带过。

## 3.5、执行规则 #2 · 隐私与敏感信息

> 高敏内容（API Key / Token / 密钥 / 私钥 / 账号口令 / 授权凭证 / 手机号·身份证·私人地址等）**禁止出现在任何产出内容中**。

1. **产出即脱敏**：产物/日志/提示词/交付物一律不含明文密钥与账号信息；确需引用时用占位 `{…}` 或资产ID，不写真值；
2. **源头隔离**：题材包/知识库若含敏感项，注入前先脱敏/隔离，Agent 只取非敏部分；
3. **头部不贴**：工作前声明 / 依据头 不得贴入密钥与账号；
4. **扫描拦截**：制片人形式核增"敏感信息扫描"检点——检出即退回＋记成长日志（错误类型：泄密）；
5. 例外：交付说明书可含**脱敏后的占位规范**，但不含任何真值。

## 4、违规处理

- 无依据产出 → 退回 / 越权创作 → 退回 / 忽略考据 → 退回 / 跨集锚不一致 → 退回
- 修改 冻结区 / 已锁定资产 未走解锁 → 回滚＋记录
- 同环节重试 >3 或 超预算 → 停机 → 上报用户
- 检出洞后不回写（负面词/特征集/规则）→ 记成长日志高频错误

## 5、版本追溯 · 检点 · 广播 · 协调

- 变更一处 → 按依据链反向算出受影响下游 → 全部标记复核，不静默通过；
- **检点留痕**：视觉检点写入镜头产物头 `检点记录`（归视觉与考据，制片人只核）；
- **变更广播**：改动落盘后 `@下游` 列需重引用的 Agent，制片人广播"请重新引用 vX"；
- **协调记录**：Agent 横向对谈结论写入成长日志「协调记录」，不留痕等于没改（见 §六）。

## 6、成长日志规范（制片人统一写入，其他 Agent 不得直写）

文件：`{项目}/06_成长日志/{项目}_第{X}集_日志.md`
写入时机：闸门退回｜用户干预｜协调结论｜每阶段定稿｜超限阻塞｜高频错误汇总
条目：

```
| 时间 | 类型(执行/退审/用户干预/协调/定稿/阻塞/错误) | 涉及Agent | 详情 | 处理结果 |
```

- 用户干预条：**用户原文一字不改**记录 + 修改目标
- 协调条：谁/对谁/改了什么/为何
- Agent 工作前声明「已读取纠错」须标具体条目号

## 7、资产分级锁定（关键帧 / 锚 / 资产图）

| 状态 | 含义 | 触发 |
|---|---|---|
| 🟢 可编辑 | 首次创建、未入索引 | Agent 创建 |
| 🟡 已锁定 | 入定稿索引、下游引用中 | 制片人归档 |
| 🔴 需变更 | 已锁定但批准修改 | 发起变更→制片人→用户确认 |

变更流程：改资产 → 同步更新锚/负面词/引用 → 重锁 → 广播下游重新引用 v新。
核心：锁定不是禁改，是**改动后必须追责同步**（资产改→锚/词库同步→下游重引→跨集一致有人负责）。

## 8、多集调度

| 模式 | 适用 | 行为 |
|---|---|---|
| 逐集串行 | 集强关联 | 一集定稿再启下一集 |
| 错开执行 | 集弱关联 | N 集进 S4 时，N+1 可启 S0/S3 |

约束：同一 Agent 同一时段只处理一集；不同 Agent 可并行不同集；资产变更时制片人广播所有在跑集。

## 9、团队化执行（开关 · 默认关）

> 个人模式无需本节点；启用团队模式时执行本节点全部规则。

### 9.1 岗位与角色（可兼）

| 岗 | 职责代理 | 可审/可写 |
|---|---|---|
| 制片岗 | 调度 · 代用户把关 · 成本/合规/出入库/日志 | 形式与一致性审核 |
| 导演岗 | S0 共商 · S1/S3 · 讲戏拆解（情绪源） | 写 大纲/拆解 |
| 编剧岗 | S0 共商 · 对白·表演稿 | 写 对白稿 |
| 视觉考据岗 | S0 共商 · S1/S2 · S3.5 关键帧 · F 检点 | 写 关键帧/自检/检点 |
| 分镜岗 | S0 共商 · S4 分镜·提示词 | 写 分镜表/提示词库 |
| 音频岗 | 后置 · S5/S6（音频侧） | 写 音频规范/配音/BGM |

一人可兼多岗；一岗可多人（多人时用 9.3 单写者 + 9.4 分支）。

### 9.2 权限（默认最小化）

- 写入权默认归属对应执行岗；跨岗写入须制片岗授权；
- 审核权属制片岗（代用户）；**裁定权属用户**（终裁/细化/创意）；
- 无授权不越岗覆盖；越权写入视同违规处理（§4）。

### 9.3 文件状态机与单写者

产物头状态：`编辑中(署名:岗) → 待审(制片岗) → 定稿(用户/制片)`
- 同一产物**同时仅一个写者**；后写与先写冲突 → 拒绝覆盖并上报制片岗仲裁；
- 定稿后再改 = 走版本追溯 + 执行规则 #1，不静默覆盖。

### 9.4 分支（平行版本）

- 目录：`{项目}/branches/{分支名}/`；
- 分支内产物头带 `branch` 标注，与主线并行；
- 合并由制片岗执行，合并后重新过对应闸门，删除被弃分支须用户确认。

### 9.5 通知

- 成长日志条目含 `@角色` 字段；闸门退回/定稿/协调/超限阻塞 即广播到对应岗；
- 产物头 `@下游` 在定稿后由制片岗广播"请重新引用 vX"。

### 9.6 隐私与最小可见

- 各岗只见其所需文件；高敏内容遵循 执行规则 #2（不落地、占位引用）。

### 9.7 团队模式下用户角色

- 用户 = 制片人兼最终裁定人（也可委托制片岗代审形式项）；创意分歧、商用放行、底图定版仍必须用户本人。
